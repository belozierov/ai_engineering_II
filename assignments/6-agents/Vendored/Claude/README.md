Evolved since the copy (to hand-port back when reunifying):

- **Fixture CC versions are a named fake constant.** Test fixtures hardcoded real CC release numbers (`2.1.201`, `2.1.204`) in JSONL literals and assertions; the values are inert parse-round-trip data, but a real-looking version reads as a pin to a specific release, which ships several times a week. Replaced with a single `version = "0.0.0-fixture"` constant per fixture enum (`ClaudeTranscriptTests/TestFixtures.swift`, `ClaudeSessionsTests/SessionFixtures.swift`) and referenced from the assertions.

- **Max-turns cutoff is a returned pause, not a thrown error.** A `--max-turns` stop arrives as a result payload with `is_error: true`, `subtype: "error_max_turns"`, exit code 1, and — measured on real payloads — **no `result` field at all**, which the old non-optional `ResultResponse.result` could not decode: the run failed as `driverFailed(decodingFailed)` and the turn's usage and stop reason were lost. Three changes: `ResultResponse.result` is now `String?` and the type gained `subtype`, `terminalReason` (`terminal_reason`), `numTurns` (`num_turns`) and `errors` (lenient per-element decoding — a non-string element is kept as its compact JSON text rather than failing the whole payload, since the `errors` shape isn't contractual); `Claude.SessionResult` gained a nested `Pause` payload (`terminalReason`/`numTurns`/`errors`) behind a defaulted `pause:` init parameter, so existing call sites are unchanged; `ClaudeSession.run(_:)` classifies `subtype == "error_max_turns"` as a paused result carrying that `Pause` instead of throwing `turnFailed`, keeps the pre-existing rule that `origin` advances to `.resume` before classification (a parsed result proves the transcript persisted, so the caller resumes rather than re-issuing a taken `--session-id`), and for every other `is_error` payload throws `turnFailed` with `result ?? errors.joined` so a missing `result` no longer crashes the error path. Tests added in `ClaudeCLITests`: max-turns payload decoding without a `result` field, structured `errors` elements captured as compact JSON, `send()` returning a paused `SessionResult`, the paused first send still advancing to `--resume`, and an `is_error` payload without `result` surfacing its `errors` as the `turnFailed` message.

Ported in from Trellis (already applied there — do **not** port these back):

- **SIGPIPE no longer kills the process when a claude peer closes its pipe first.** `Claude.ToolProxy` pumped host bytes to its output with a bare `FileHandle.write(contentsOf:)`. On Darwin that raises SIGPIPE once the reader is gone, and the signal fires before `write` can return `EPIPE`, so the `throws` signature never helps — the process just dies. claude routinely exits before the host on a normal turn, and `ToolHost`'s registration-confirmation loop keeps pushing `tools/list_changed` for up to three seconds, so bytes are genuinely in flight during teardown. In `ClaudeMCPTests` this killed the whole test runner roughly once in fifteen runs, reported only as `exited with unexpected signal code 13` with no failing test named. New `ClaudeDomain/FileHandle+BrokenPipe.swift` adds `package` helpers `suppressBrokenPipeSignal()` (an `fcntl F_SETNOSIGPIPE` wrapper) and `writeWhileReaderIsOpen(_:)`, which returns `false` on EPIPE and rethrows everything else; `ToolProxy.run(port:input:output:)` suppresses the signal on its output and the output pump treats a closed reader as EOF. The socket direction is handled symmetrically: a send that fails with `NWError.posix(.EPIPE/.ECONNRESET/.ENOTCONN)` ends the proxy cleanly instead of throwing, since a torn-down host means the run is simply over. `ProxiedClient` applies the same suppression to the descriptor MCP's `StdioTransport` writes to. `ClaudeMCPTests/ToolProxyTests.swift` is the deterministic regression test — it closes the output reader *before* the peer sends, so there is no race to lose, and it reproduces the original signal 13 exactly when the fix is reverted. The helper lives in `ClaudeDomain` rather than `ClaudeMCP` so `ClaudeCLI` can use it without importing an MCP module for a POSIX primitive, and it is `package` rather than `public` so it stays out of the published API.

- **The CLI driver survives a claude child that exits before reading its prompt.** `ClaudeProcess.write(_:to:)` wrote the whole prompt into the child's stdin under `try?`, which catches nothing when the failure arrives as SIGPIPE — a child that dies early (bad flags, auth failure, crash) took the host app down with it. It now calls `suppressBrokenPipeSignal()` on the stdin handle first, so the write merely fails; the undelivered prompt is never the real story, and the child's exit code and stderr still reach the caller as `driverFailed(processFailed(...))`, which is the diagnosis worth having. Regression test `promptWriteSurvivesChildThatNeverReadsStdin` in `ClaudeCLITests` uses a stub that exits 9 without reading stdin plus a prompt far larger than the pipe buffer, so the write must block and then fail rather than vanish into the buffer.
